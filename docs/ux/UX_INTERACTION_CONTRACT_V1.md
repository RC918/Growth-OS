## 1. 主要使用旅程：設計交付契約

**入口 → 分析 → 人工審稿 → 獨立授權 → 執行 → 遠端回讀 → 成效**。介面須將「審核內容」和「准許對外修改」分離；完成初步分析後不能跳過平台/帳號/資產/欄位權限。

| 代碼 | 起始 / 動作 | 前置條件 | 預期顯示或轉移 | 不允許 |
|---|---|---|---|---|
| U01 | 輸入 WordPress 網址 → 分析 | URL 可辨識且可讀 | 來源、受影響資產、限制和可追溯分析資訊；資料不足給明確補救 | 冒稱已連接後台 |
| U02 | 輸入 YouTube 網址 → 分析 | 可識別影片/頻道 | 僅顯示可在已授權範圍內完成的候選改善 | 將單部影片權限擴成整個頻道 |
| U03 | 非法/不支援 URL | 無有效 URL 或平台不支援 | 原欄位顯示錯誤及有效示例，保留輸入 | 進入成功頁 |
| R01 | 開啟修改前／後對照 | 提案附來源/依據 | 可展開差異與證據，三個動作：核准草稿／要求修改／暫緩 | 核准草稿即發文 |
| A01 | 第一次連接平台 | 無有效連線 | 選擇平台及帳號，顯示 OAuth/API 能力與缺失 | 要求在聊天室輸入密碼 |
| A02 | Review-first 發佈授權 | 草稿已核准、連線有效 | 顯示**實際資產、欄位、原值、新值、可見性、失效時間**，最終按鈕明示這是對外寫入 | 以模糊的「下一步」隱藏外部修改 |
| A03 | 限定自治授權 | 使用者明確 opt-in | 帳號、資產集合、允許欄位、次數/期間、時間窗、有效期、撤銷入口可檢視 | 默認勾選/無限期/跨平台套用 |
| A04 | 撤銷／授權過期 | Grant invalid | 顯示 NEEDS_ASSISTANCE 與重新授權；保留已完成紀錄 | 新發送任何遠端寫入 |
| A05 | YouTube 僅描述授權 | description only | 標題編輯控制項停用並顯示原因 | 寫入 title |
| A06 | WordPress 文章文案授權 | 僅允許文章/頁面欄位 | 商品價格、庫存、結帳、刪除操作皆不可選 | 以「內容優化」名義修改商業交易欄位 |
| E01 | 執行時暫停 | 有排隊任務 | 停止派遣新寫入；正在進行的遠端操作標示「核對中」 | 顯示所有工作已取消 |
| E02 | 恢復自動作業 | 狀態為 PAUSED | 重查授權、目標版次、遠端資料及剩餘額度後才恢復 | 無條件重播原請求 |
| E03 | 遠端請求逾時 | 寫入結果未知 | RESULT_UNKNOWN +「先查遠端狀態」，提供重試前風險提醒 | 直接重送寫入／宣稱失敗或成功 |
| V01 | 遠端讀回一致 | 對應欄位/版次與預期符合 | VERIFIED、讀回時間與來源、原稿/新版可檢視 | 僅 HTTP 2xx 就標成 Verified |
| V02 | 指標資料尚未到齊 | 平台無最新成效資料 | 顯示來源、區間、等待狀態和最後更新時間 | 虛構曝光、點擊、排名 |
| F01 | 申請恢復原版本 | 遠端未被第三方更改，權限仍有效 | 顯示恢復範圍、差異及確認；回讀成功後才顯示 RESTORE_VERIFIED | 將「返回畫面」稱為「完成回復」 |
| F02 | 版本衝突 | 原稿、AI 版、遠端版三者不一致 | 停止覆寫；提供「檢視三方差異」「保留遠端內容」「建立新的恢復提案」 | 一鍵強制覆寫、直接宣稱已回復 |

**介面用語規則：** 「模擬」只能表示 Figma 演示；模擬授權不得被誤導成正式平台授權。「草稿已核准」「已授權」「已送出」「遠端已驗證」「成效已觀察」五個狀態不可合併成一個「完成」。

### 截圖觀察（2026-10-23）

直接檢視 [手機同意 38:151](https://www.figma.com/design/jOfuk31i2BrJmMvXs25B59?node-id=38-151)、[手機回讀 38:175](https://www.figma.com/design/jOfuk31i2BrJmMvXs25B59?node-id=38-175)、[桌面衝突 37:302](https://www.figma.com/design/jOfuk31i2BrJmMvXs25B59?node-id=37-302) 的實際渲染圖，發現：

1. **手機同意頁：P0／未完成。** 同一授權摘要同時呈現 WordPress 與 YouTube，仍缺少選定帳號、資產、欄位及有效期的可操作控制；「模擬授權 → 驗證」是一條展示捷徑，應在原型中加入真正確認與拒絕路徑。
2. **手機驗證頁：P1／文案待改善。** 已有「示範資料」提示和不宣稱已連接真平台的文字；但必須進一步明確區分「等待遠端回讀」「回讀一致」「回讀不一致」「未知結果」，同時顯示來源及時戳。
3. **桌面版本衝突：P0／未完成。** 畫面已明確說明第三方編輯與禁止覆蓋，方向正確；然而目前可見的兩個底部按鈕均為「返回」類導覽，缺少真正的「檢視差異／保留內容／提出恢復草稿」決策入口。
4. **三張截圖均不作為完整互動驗收。** 僅能確認靜態視覺與可見文字，無法由截圖證明 Figma reactions、鍵盤操作或真實 API 守衛。

## 3. 響應式與無障礙最低驗收

- 需驗證 320、375、390、768、1024、1600 px 視窗，不可只檢查 390 px。
- CTA 必須位於可見且可操作的容器，不得與告警或法務文案重疊；重要行為不得只靠顏色區分。
- 可互動控制的手機觸控目標至少約 44 × 44 CSS px；另檢查安全區、虛擬鍵盤覆蓋和放大文字情境。
- 一般文字色彩對比至少 4.5:1、大型文字至少 3:1；焦點樣式需可見，鍵盤可完成主要決策。
- 中文 2 行以上、最長標題、較長平台名稱及授權摘要都要測試折行。
- 「結果成功」「公開更新」「回復完成」均需對應實際條件；模擬畫面持續顯示醒目的概念演示提示。

## 4. 原型驗收案例：先負向、再正向

每條案例都需在 Figma prototype 執行，留下可開啟的起點/終點節點和畫面截圖。不能以「畫面存在」替代點擊驗收。

- [ ] T01 空 URL／非法 URL 阻擋下一步，輸入可恢復。
- [ ] T02 WordPress 審核草稿後，未授權時無法對外發佈。
- [ ] T03 YouTube description-only 權限下 title 控制不可操作。
- [ ] T04 拒絕授權後保持 WAITING_FOR_REVIEW，沒有模擬成功跳轉。
- [ ] T05 自治範圍改動後顯示更新的授權摘要，過期/撤銷無寫入路徑。
- [ ] T06 執行中暫停後顯示待核對工作，不將 in-flight 視為已撤銷。
- [ ] T07 寫入逾時轉 RESULT_UNKNOWN，先回讀再提供安全重試。
- [ ] T08 回讀不一致轉 NEEDS_ASSISTANCE，不給 VERIFIED 徽章。
- [ ] T09 第三方修改導致 RESTORE_CONFLICT，不能自動覆寫。
- [ ] T10 正向流程：單一平台、有效授權、模擬回讀一致，展示 VERIFIED 與來源證據。
- [ ] T11 320/375/390/768/1024/1600 px 的按鈕、文字、卡片與側欄無遮擋，必要時提供收合。
- [ ] T12 正式視覺參考 v1 逐頁比對：間距、資訊層次、字體與對比均有截圖和結果。
