# Sprint 2｜身分、網域與匯入驗收門檻

狀態：設計與驗收規格，尚未在雲端實作。此文件界定何時能從本機 CSV 交易原型進入有真實商家資料的 Staging。

## 信任邊界

1. 使用者登入後，服務端從已驗證的 session 取得 `user_id`。請求 URL 或表單提供的 `organization_id` 只作查找鍵，不作身分證據。
2. 每次讀寫以 `user_id` 查 `organization_members`。`owner` 可驗證網域、授權匯入與刪除；`editor` 可預覽與匯入已驗證站點；`viewer` 僅能讀有權限的報告。未加入組織一律回 404，避免洩漏另一租戶是否存在。
3. 站點必須同時屬於該組織且已驗證。所有匯入批次與分段只用服務端確認的 `organization_id`、`site_id` 寫入；資料庫啟用 RLS，服務層再檢查一次。Service role 金鑰只在服務端使用。
4. 匿名公開掃描與工作區報告分開。匿名 scan ID 不授權連接 GA4、上傳 CSV 或保存長期報告。

## 網域驗證

- 建立站點時只接受正規化的 HTTPS origin。服務端產生每站獨立、不可猜測且有到期時間的 challenge，儲存其摘要，不保存明文於日誌。
- Owner 在 DNS 新增指定 TXT 記錄。驗證工作者查詢權威可觀察的 TXT 值，精確比對 challenge，成功後寫 `verified_at`、驗證方法、驗證時間與稽核事件。過期或輪替後的值無效。
- 驗證應有頻率限制；站點轉移、移除或長時間不再控制網域時可撤銷。掃描公開網址不會自動取得網域所有權。
- 不把 DNS TXT 驗證當成使用者登入。工作區成員權限仍須獨立檢查。

## CSV 匯入流程

1. 已授權成員在已驗證站點選來源、上傳彙總 CSV，預覽欄位映射與缺值。前端不得送出自由指定的已授權 `user_id`。
2. 服務端先檢查檔案大小、格式、個資與病毒政策，檢查所選來源能產生的指標；用資料來源、收集時間、定義版本與涵蓋日期記錄品質資訊。
3. 交易中檢查站點權限、`(organization_id, source, idempotency_key)` 唯一性與輸入指紋。同鍵同內容回原批次；同鍵不同內容回衝突。批次與分段一同提交或一同回滾。
4. 不跨來源相加「廣告點擊」與「GA4 session」當作相同母數；缺值為 `null`。金額以幣別分開，未取得退款資料時不聲稱淨收入。
5. 只保存匯入所需的彙總資料；正式保存與刪除時限應由 Owner 在上線前核定，並實作匯出、刪除及稽核。

## 必須通過的驗收情境

| 情境 | 預期結果 |
|---|---|
| 未登入或非成員帶入別人的組織／批次 ID | 401 或 404；不能讀、改、刪或推知資料 |
| Viewer 嘗試建立站點、驗證或匯入 | 403；資料庫不新增批次 |
| A 組織成員使用 B 組織站點 ID | 404；沒有部分寫入 |
| 未驗證站點匯入 | 拒絕；公開掃描結果不能繞過驗證 |
| 同鍵同檔／同映射重試 | 回同一批次 ID；分段數不變 |
| 同鍵但檔案、映射或站點不同 | 衝突；原批次不變 |
| CSV 缺欄、重複分段、錯誤幣別、格式錯誤 | 有清楚錯誤與行號；不留半批資料 |
| 匯入零、空白、不同來源的指標 | 零與未知分開；來源不混用 |
| RLS 直接以兩個不同登入身分測 SELECT/INSERT/UPDATE/DELETE | 跨租戶操作全部失敗；不能只靠 API 測試 |

## Staging 放行證據

提供部署網址與版本 SHA、登入／授權 API 測試、Postgres migration 與 RLS 測試、真實 DNS TXT 驗證、端到端匯入與重試測試、錯誤／刪除流程、worker 網路與掃描安全檢查。上述證據齊備前，不接受真實客戶 CSV 或對外開放匯入 API。

目前 `prototype/csv-import` 僅驗證純資料函式與本機 SQLite 交易；沒有任何身分、DNS、RLS 或雲端證據。
