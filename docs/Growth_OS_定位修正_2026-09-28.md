# Growth OS 定位修正｜2026-09-28

## 決策

產品的第一承諾是協助企業與多媒體創作者取得**更多相關流量**：找需求、提出有證據的內容／頁面機會、經人審核後執行、量測曝光與到站訪問。轉換診斷與詢盤／訂單追蹤是第二層，判斷流量品質與商業價值。不能把「訪客未註冊」當成整套產品的定義。

早期文件把創辦人的廣告流失案例升成 Visitor-to-Customer Leak Map 的第一模組，首頁又照此案例寫成主標。這是試驗切入點與產品定位混淆。本文件優先於《Commerce_Growth_系統設計_v0.1.md》中對第一模組與開發順序的描述；既有公開掃描、CSV 與 RLS 程式仍可作為可重用的診斷基礎，不代表流量模組已完成。

## 客群與試點

| 層次 | 目前選擇 | 驗收口徑 |
|---|---|---|
| 產品範圍 | 需要商業行為的企業與多媒體創作者 | 不宣稱所有行業已驗證 |
| 第一試點 | 有自營網站、多商品／規格的中小電商與貿易商；使用 Good Morning Digital 的全新產品站累積基線 | 需求機會、搜尋曝光、相關訪問、詢盤或訂單 |
| 後續客群 | 創作者及其他服務業 | 另驗證平台分發、作品、預約、訂閱／贊助等口徑，不套用電商訂單模型 |

## 產品循環與量測

1. **需求與受眾**：記錄產品／作品、地區、客戶問題、來源、證據與禁止宣稱。沒有 GSC 時由公開且可核查的一手素材建立假設，標記未知搜尋量。
2. **機會與執行**：排序少量有原創價值的頁面、內容或分發更新；記錄人工核准、版本、發布時間與成本。
3. **能見度與流量**：GSC 的曝光／點擊、GA4 的到站訪問、AI 提及各自呈現，不能相加或把曝光稱為訪問；設定觀測窗與基線。
4. **商業成果**：按客群追蹤合格詢盤、淨訂單、預約或訂閱；流失診斷是改善成果的子工具，不能以註冊率代替所有結果。

第一階段的主指標是**相關到站訪問**（來源與目標受眾可辨），輔助指標是搜尋曝光／點擊與有來源的機會完成數；商業事件是品質護欄。若新站基線為零，先報原值與資料完整度，不能聲稱百分比成長或保證自然流量。

## 下一階段工程順序

1. 補 Business Profile、來源與機會資料契約：需求題目、來源、目標受眾、假設、信心、核准狀態。
2. 做可審查的機會清單與人工核准流程；先用合成資料驗證排序與版本記錄，再用自有產品站的一手素材建立試點。
3. 建立新站 GSC／GA4 與事件基線；需由 Owner 完成 Google 站點所有權與授權步驟。未連接前 UI 明示未知，不顯示假成效。
4. 選 3–5 個有獨特資料的內容／頁面候選，逐項事實查核與預覽。公開發布前取得 Owner 核准。
5. 將既有訪客流失掃描放在第二層「流量進站後」診斷，不阻塞需求、內容與能見度主流程。

正式名稱、網域、付費工具與對外發布仍各自待 Owner 決定。這份校正不等於保證 SEO、AI 引用、流量或營收。
