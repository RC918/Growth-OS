## 1. 要驗證的生意

產品優先服務電商與貿易商，長期服務需要流量的企業與創作者；資料設計保留產品／作品、受眾、渠道與流量指標，創作者專屬流程列為未來規劃。核心任務是找出可驗證的需求，協助產出、更新與分發有原創價值的頁面或內容，增加相關搜尋曝光與到站訪問，並追蹤詢問、訂單、預約或訂閱。第一個狹窄試點仍是**有自營網站、管理多個商品或規格，並向海外或多語市場銷售的中小型電商／貿易商**；創作者是後續驗證客群，尚未把其專屬資料模型當成第一版已完成。Owner 本身有小企業實務經驗，先以其真實作業建立第一份問題圖譜與測試情境，清楚標記為「創辦人經驗」；之後才用外部商家驗證可遷移性。內部試點是 Good Morning Digital Co., Ltd. 旗下**全新產品與全新網域**；Morning Ai 不作試點網站。工作標題採 `Growth OS by Good Morning Digital`；這是產品描述而非已清理權利的獨占品牌。正式產品名稱、網域及商標須另行確認；工程代號仍為 `Growth OS Pilot`。

核心承諾：每週找出一項有依據的**獲取相關流量**機會，經人審核後協助執行，分開回報搜尋／AI 能見度、到站訪問及可歸因的商業成果。流量增長是第一目標；轉換缺口診斷是衡量流量品質與提高成果的第二層工具。首個創辦人問題（Facebook、Telegram、LINE／簡訊導流後訪客未註冊）保留為一個診斷案例，不代表整套產品只處理訪客離站。沒有基線時不推定流量提升或流失原因；無法追蹤成交時標示「未歸因」。

主要操作流程：`對話提出目標 → 收集必要資料 → 成長計畫與工作卡 → 草稿確認 → 執行進度 → 真實成長數據`。系統每次詢問一至兩項缺少資訊；沒有網站仍可保存目標，需要網站資料的工作才要求補齊。對話中的推論必須由使用者確認，資料庫保存的狀態才是正式進度。

| 階段 | 交付與驗收門檻 | 暫不納入 |

## 3. 第一版產品需求與實作狀態

第一版完成網站自然搜尋流量的一條流程；優先電商與貿易商。其他渠道目標可以記錄，明示目前支援範圍。社群／影音執行與創作者專屬能力為未來規劃。

| 能力 | 已實作基礎 | 待開發或未來規劃 |
|---|---|---|
| 對話提出目標 | 固定問題引導、必要資料收集、目標與不可覆寫問答、修正再確認及跨登入讀回已實作／驗收；既有企業與機會表單保留 | 待開發：真實自然語言理解、推論來源與使用者修正確認；輸出結構／來源／確認離線契約已實作但未接模型或UI；固定問答不代表 AI 理解 |
| 成長計畫與工作卡 | 機會清單、來源證據及人工審核 | 待開發：可修改的計畫版本、工作卡、缺資料與下一步提示，連結目標及既有機會 |
| 草稿確認 | 使用者輸入內容、不可覆寫版本、owner 審核 | 待開發：真實模型產稿及來源約束；新版不得沿用舊版核准 |
| 執行進度 | 已核准草稿的內部行動計畫 | 待開發：保存執行事件、失敗與冪等重試。第一版只執行內部整理、生成、保存與規劃；對外發布為人工操作 |
| 成長數據 | 搜尋資料驗證、合成標記、觀測版本保存與讀回 | 待開發：連結目標／工作、歷史分頁、計算版本。真實資料授權與來源核實另設驗收里程碑 |
| 權限與稽核 | 測試環境 owner/viewer、組織隔離、審核與版本 | 必須保留；新資料與操作沿用組織隔離。多工作區切換與 editor 尚非已完成功能 |
| 後續能力 | 公開頁面診斷、離線轉換原型可重用 | 未來規劃：轉換優化、週報代理、GA4/CRM、Ahrefs、多渠道自動發布及創作者專屬流程 |

首頁建議文案：「想為你的作品或產品帶來更多流量嗎？」與「告訴我你正在做什麼，我們一起開始。」入口放自然語言輸入；工作區以對話、工作、成長組織體驗，版本、審核及資料管理由工作卡展開。桌面可用對話與當前草稿並列；手機切換視圖。這是待實作設計，現有管理介面仍保留。

草稿生成、核准、內部規劃、實際發布、量測是不同狀態。完成草稿不能顯示「已發布」；等待外部操作時顯示「待人工發布」。發布狀態須有可核對證據，使用者聲明與系統核實分開。合成資料只能標為測試；人工匯入若未核實來源，標為「提供者聲明、來源未核實」；沒有資料顯示「尚未取得資料」。

## 4. 第一個試驗設計

新品牌初期先驗證「從需求與內容機會取得更多相關訪問」。建立產品／受眾檔案與需求機會清單，以有來源的客戶問題、商品資料及 GSC（若已連接）排序；選少數頁面或內容由 Owner 核准發布；以 GSC 曝光／點擊和 GA4 訪問建立基線，分開檢視商業事件。AI 提及與搜尋曝光不等於實際流量，也不保證排名。Visitor-to-Customer Leak Map 保留為第二層診斷：公開掃描只指出可見著陸頁摩擦，授權資料才可量測漏斗。Owner 的廣告經驗是這一子模組的案例，不代表所有客群的首要問題。先以電商／貿易商試點，之後訪談創作者並補其專屬事件與管道。尚未實作的功能標示「規劃中／開發中」，不能作流量或收入成果宣稱。定位修正詳見《Growth_OS_定位修正_2026-09-28.md》。

第 0 天設定 GSC、GA4、表單/候補名單事件和站點所有權。新站沒有歷史基線；從上線日期起累積週趨勢，也以工具完成率、合格候補名單和實際試用作更早的需求指標，不能主張因果。商家的主要轉換分兩條：電商為訂單／毛利／退款；貿易商為合格詢盤／報價／成交。先做 3–5 個有原創價值的頁面，人工核准再發布；每週檢查抓取/索引、query、頁面與 CTA。至少觀察 8–12 週後才判斷 SEO 初期方向，不承諾一定見到排名。

**成功條件**：至少 1 頁有實際索引和相關 query 的曝光；免費工具被真實目標客戶完成、或產生合格試用詢問；展示一條可核對的行動至結果證據鏈；設計夥伴願意再次使用或付費。第一批數值門檻要在訪談後按實際基數設定。這是逐層驗證，不是承諾排名與營收。

**停止／轉向條件**：資料授權無法取得、每頁無獨特價值、維護單位成本超過預期效益、轉換定義不可靠、連續實驗沒有實際需求證據。記錄原因後縮小範圍或換市場。

## 5. 資料模型與連接器

長期規劃核心表（不是已部署清單；實際已部署結構以 `supabase/migrations` 為準）：`organizations`, `sites`, `business_profiles`, `source_connections`, `entities`, `claims`, `claim_sources`, `opportunities`, `actions`, `approvals`, `content_versions`, `page_daily_metrics`, `conversion_events`, `revenue_events`, `proof_links`, `audit_events`。每筆資料有 `organization_id`；跨租戶隔離、最小 OAuth 範圍與秘密輪替在進入付費多租戶前驗收。

本次新增資料設計需求為目標、對話訊息、計畫版本、工作項目與執行事件；具體表名及 migration 待設計。關係為目標 → 計畫 → 工作 → 既有機會 → 草稿版本 → 行動 → 發布證據 → 觀測版本。每筆組織資料沿用 RLS，採增量 migration，不覆寫歷史。

`proof_links` 的規劃連接 action → page → observation → event；包含 `evidence_type`（observed/associated/estimated）、`source`, `collected_at`, `window_start/end`, `method`, `limitations`。同一交易 ID 去重，退款和取消沖回。僅當 CRM/訂單能確定連到 lead 與 action，才顯示「歸因營收」；其他情況顯示「相關期間營收」或未知。SEO 觀測數據不能單獨建立因果。

連接順序：GSC 手動匯出或 OAuth → GA4 → 自有表單/CRM → Ahrefs 只在有授權和商業需求時啟用。Ahrefs API 使用量與多客戶展示權利須實際查訂閱與合約；設限額、快取、來源註記，避免透支。先不強制依賴其 API。

2026-09 官方資訊：Google 已推出 Search Console 生成式 AI 獨立報表，但目前公開的 Search Analytics API 文件 `type` 僅列 web/image/video/news/discover/googleNews。**不能預設生成式報表已可由 API 擷取**；第一階段以介面匯出或有核准的替代取得方式驗證，再實作對應連接器。Ahrefs Brand Radar 有 mentions/citations 等 API，但屬其樣本與模型，不能與 GSC 曝光或真實訪問相加。

## 6. 任務與批准規則

| 動作 | 系統行為 |
|---|---|
| 收集資料、生成草稿、內部比對、建立週報 | 可自動執行，保留記錄 |
| 修改正式頁面、公開比較或價格宣稱、發送對外內容 | 先預覽、事實查核與 Owner/受委託編輯批准；可回滾 |
| 付費廣告、訂閱採購、外部發布合作、變更付款或資料共享 | 明示金額與影響後由 Owner 核准 |
| 刪除或 410、網站遷移、大量頁面發布 | 個別審查依據、影響範圍與復原計畫 |

營運代理依資料/動作區分，不需第一版同時建九個獨立 AI Agent。採事件與狀態機；複雜流程真有需要時再導入 LangGraph。第一版以 PostgreSQL 常規欄位加 JSONB 變動屬性，不預設所有東西用 EAV/pgvector。

## 7. 原計畫校正

- 結構化來源和人審能降低幻覺，不保證 100% 正確；價格會變、來源可能失效。
- Google Indexing API 僅適用特定職缺/直播頁；一般 pSEO 用 sitemap、正常內鏈、可抓取與內容品質。
- Schema 是讓符合規範的內容有機會呈現特定搜尋外觀，不保證 Rank 0；Core Web Vitals 應看實際指標，不能把 Lighthouse 95 分當流量保證。
- 90 天低曝光先診斷意圖、季節、索引、內容與競爭，再決定補強、合併或移除。
- AI 提及、被引用、搜尋曝光、訪問、lead、收入是不同口徑；統計來源、分母、樣本與時間須可見。
- 早期關鍵里程碑是單一有效需求與使用者留存，不是假設 500–2,000 頁後自然變現。
