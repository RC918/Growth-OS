# 內容內部執行方案｜獨立 Staging

## 目的與範圍

把最新版已核准草稿接到可追溯的執行準備：建議頁面路徑、發布後觀察的指標、撤回方式。這是內部方案，不建立網站頁面、不產生公開網址，也不代表已帶來流量。實際發布時間與成效量測屬後續階段。

## 資料與權限

- `content_action_plans` 每個草稿版本最多一筆，保存建立人與時間。新版草稿不覆寫舊版方案。
- `plan_content_action` 只允許該工作區 owner 對已核准機會的最新版、已核准草稿建立方案；路徑限定相對路徑。拒絕空值、舊版、退回或未審核版、重複提交、viewer 與跨工作區操作。
- 工作區成員僅能依 RLS 讀取自己的方案，沒有直接新增、修改或刪除權限。成功建立時寫入 audit event。

## 驗證

- Growth OS 獨立 Supabase Staging migration `content_action_plans`（版本 `20260929162849`）已套用。
- `supabase/tests/content_action_plans_staging.sql` 在交易中驗證權限、狀態、路徑、唯一性與 audit；測試結尾回滾，沒有保留合成方案。
- Workspace API 與單欄頁面同步增加內部方案表單及歷史顯示；待本次 CI、預覽部署及真實瀏覽器驗收記錄補齊。

目前第 2 版草稿已退回，owner 需建立並核准修訂版後才會看到方案表單。無正式網域、公開發布、真實流量基線或流量成果。
