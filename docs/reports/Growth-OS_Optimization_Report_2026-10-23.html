2. 三項目標的判斷

目標判斷下一個必須取得的證據
一人公司、自動化營運方向明確。藍圖第 10 節已有每週工作、持久任務、成本、通知與恢復要求；持續產品服務目前未獲本輪實測證明。服務／執行程序重啟後，仍能接續原任務；連續兩輪產生有依據的工作或「本輪不需改動」結論。
分享對話的 UX 與授權方向已落入 #35 文件：共用介面、五主畫面、右側唯一必要決策、核稿與發布授權分開、限定自治、恢復衝突。尚非完整實作。選定 Beta 所需畫面，逐項對應產品路由、後端能力及同版操作結果。
10/31 受邀 Beta可作條件式目標，尚無足夠證據承諾。主要關鍵路徑是真實接線、託管部署與整合驗收。受邀者用自己的受支援網址，在單一入口完成取得成果、核稿、保存、重新登入、授權、發布、讀回與回訪。

3. 先消除藍圖與 UX 的範圍衝突

現行唯一有效藍圖是 v2.0，雖檔名仍含 v1。首客群為電商／貿易商，最小閉環是一個產品頁、一種改善包、一個平台與可信量測。#35 UX 草案則把網站／YouTube、創作者、雙平台與限定自治放入 V1 設計目標。兩者可以共用長期架構，但不能同時當作 10/31 放行範圍。

  1. 10/31：WordPress 單站、單一受支援產品頁、title／搜尋摘要／產品描述改善包；逐次確認公開寫入；精緻桌機與響應式手機流程。
  2. Beta 後第一里程碑：持續監測、每週工作、必要提問與有限授權；以兩輪可恢復接續驗收。
  3. 再後續：YouTube、批量頁面、多渠道、更多 Agent 與收費。保留共同介面與 adapter 邊界，當前不承諾可用。

需要優先釐清的技術細節：WordPress／WooCommerce 頁型與欄位映射。頁面標題、SEO 外掛的 meta description、商品長描述並非同一欄位。列出實際支援的內容類型與外掛，驗證 API 與公開 HTML 中套用位置；若現有 adapter 只支援一般文章／頁面，不可用一般頁發布成功推定 WooCommerce 商品頁全流程成立。這是建議核查項，並非本輪已證實的缺陷。

4. 使用者應走的完整流程

階段使用者看見／需要做系統必須成立
貼網址一個網址欄位；可支援範圍與失敗補救清楚安全取得真頁面；分辨頁型與目標產品，不能悄悄換成示範資料。
第一份改善成果原文／建議／理由；最多優先呈現 1–3 個必要改善真實生成與來源綁定；不捏造規格、價格、認證或排名保證。
核稿與保存微調、確認事實；稍後回來仍可接續版本保存、跨登入完整讀回；編輯後舊核准失效；正確租戶與權限。
平台連接與發布授權看懂站點、目標頁、欄位、原值／新值及有效期，再確認本次公開修改連接、草稿核准、發布許可三件事分開；服務端驗權。
發布與驗證分清待送出、已送出、核對中、已核實；可看發布證據同版同頁；API 及適用公開輸出讀回；結果未知先查原操作。
回訪與持續服務已完成、需要我決定、目前觀察、下一步量測與版本、頁面、發布時間連結；沒有資料明示等待／未知；可選擇持續觀察。

5. 發布之後的 SEO／GEO 服務與授權

應接續，但不增加一個籠統的「同意 SEO／GEO」關卡。第一份改善包本來就服務搜尋可見度；發布後延伸到持續觀測、機會判讀、下一輪建議，再依有效授權改站。發布前便定義基線與量測來源，沒有歷史資料就明示，不能回填假基線。

層級可讓使用者理解的授權範圍
觀測與準備「持續觀察這一頁，準備下一份改善建議」明示來源、頻率、通知及用量；一方數據需各自有效連接。
逐次發布（Beta 預設）「這次將以下內容更新到這一頁」確認確切版本、目標與欄位；核稿不自動等於公開寫入。
限定自治（後續）「在以下範圍內自動處理」站點、資產集合、欄位、次數、成本、時間窗、期限及撤銷；服務端拒絕越界。

SEO 成效、GEO 提及／引用、到站訪問、詢問與成交分開。產出 FAQ 或結構化建議不等於 AI 引用增加；沒有有效資料來源就不顯示成效數字。GEO Beta 階段可先提供內容建議與明示的可觀測範圍，未驗證的跨 AI 平台引用監測不列為完成能力。

6. 工程與交付優化清單

優先工作包／具體優化完成條件
P0統一 Beta 分支與部署入口；列 #31/#35/#36/#38 等實際依賴，只整合必要部分固定網址對應 release SHA、資料庫版本與功能開關；不讓使用者往返原型、工作台及匯入工具。
P0接通真來源與模型；分開來源摘錄模式與真正改善模式用受支援真網址產出有用文本；來源、模型／模板版本、請求與成本可追查；失敗不回退成假成功。
P0新 Console 接真 Auth、持久保存與 tenant／角色約束Save → Logout → 全新 session → Login → 完整讀回同版；viewer、跨租戶、過期版負測成立。
P0必要核稿、授權及發布規則在可信服務端落實繞過 UI 直接呼叫 API 仍拒絕未核准、舊版本、錯頁、越權與過期許可。
P0WordPress 一頁發布閉環與安全恢復正確欄位／頁型、有效權限、原始快照、唯一操作、遠端讀回；第三方編輯後阻止靜默覆寫。
P0受邀加入與正確站點連接新受邀者可進入正確工作區；只有必要角色能授權；錯連帳號／站點可取消恢復。
P0中斷、逾時與重複點擊保留成果；未知操作查原 ID；重啟／重登入後不重複發布；明示尚未覆蓋的恢復邊界。
P1量測關聯與回訪目標頁、發布時間、來源、期間、基線及後續觀測可核對；未連接／故障／等待／真零分開。
P1產品級操作與錯誤可觀測性同一任務串起來源、生成、保存、發布與讀回；可用非秘密 ID 診斷；有成本與有界重試，不讓 Owner 搬 log。
P1真人操作與視覺驗收少量受邀者走完整流程；記錄完成、卡點、等待、求助與內容採用，而非只記測試數。

既有資產應重用：Auth／RLS、owner/viewer、版本歷史、來源安全、受控 WordPress 發布與恢復、已驗過的 unknown reconciliation。舊成功不能直接為新 Console 接線背書；也不應因新介面而重建全部框架。

內容品質不能省略：對每個候選比較原文與建議，核是否準確描述同一產品、是否真的更清楚、是否含無依據宣稱，以及使用者是否願意採用。生成成功或引用存在本身不代表改善有價值。可用少量已核對的真案例做固定品質檢查，但不可用固定答案冒充線上模型。

7. UX：保留精緻度，補足可操作性

保留左側導覽、中央成果、右側唯一必要決策、可收合工作狀態。首次入口突出貼網址；回訪優先呈現待決策、已發布與下一步。來源、版本、稽核及工程細節可展開。使用者不應輸入 SHA、匯入 JSON、在多個獨立示範中搬資料。

  1. 先修手機授權：單一流程只顯示目前選定平台、帳號、資產、欄位與期限；補確認、取消與拒絕分支。不能把 WordPress／YouTube 混在同一授權摘要。
  2. 補版本衝突的真決策：檢視差異、保留遠端、建立新恢復提案；只有「返回」按鈕不足以處理衝突。
  3. 拆開成功狀態：草稿已核准、已授權、已送出、遠端已核實、成效已觀察不能合併成「完成」。
  4. 工程只接當期必要畫面：先做 URL、成果／核稿、保存／回訪、單次授權、發布結果、錯誤恢復；限定自治與 YouTube 保留後續規格。
  5. 補真正操作驗收：非法 URL、拒絕／撤銷／過期授權、未知回應、讀回不一致、衝突恢復皆能操作；靜態截圖只當視覺證據。
  6. 檢查響應式與無障礙：依既有規格覆蓋 320/375/390/768/1024/1600、200% 文字、鍵盤與焦點、中文長字串及手機鍵盤遮擋；用共用元件與 tokens 維持精緻度。

#35 尚為設計交接草案。優先把本輪必須的畫面完成視覺／互動驗收與技術能力對照，再在既有有效授權範圍安排工程；不因本報告而自動合併或部署。

8. 一人公司：工程自治與商家營運分別驗收

項目最小可行方式驗收
工程自治Dot 統一優先順序；既有 Codex 執行；Reviewer 獨立核同版；完成事件／實際 controller 接續有任務 ID、接收／完成回條、審查結果與下一包；沒有真 controller 不稱全天候運作。
商家產品自治先一頁：觀測 → 辨別變化 → 必要問一題 → 備草稿 → 依授權處理 → 摘要連續兩輪真觸發、持久任務、用量限制、失敗恢復、通知與回訪；重啟後可接續。

不必先成立 20 個 Agent。先用來源理解、內容改善、宣稱檢查、發布執行、觀測排序等責任邊界，重用現有模組與任務紀錄。只有工作量或權限隔離確有需要才拆成獨立 Agent，避免先增加協調成本。

每輪工作可以得出「本週不改，繼續觀察」，但需記錄原因、資料缺口、下一次檢查條件與成本。持續營運不等於每週強制改寫。對外寫入仍遵守當下有效授權；工程自治不會自動取得商家發布權。

10. 最終放行清單與成效指標

  1. 一個固定入口、明確候選版本、可恢復部署與可追查的操作紀錄。
  2. 受邀者能進正確租戶，以受支援真網址取得有來源的真實改善建議。
  3. 能微調、保存、登出、新 session 登入並完整讀回；viewer／跨租戶／舊核准被正確限制。
  4. 服務端驗核確切版本、頁面、欄位與有效發布許可；直接 API 無法繞過。
  5. 發布到正確 WordPress 位置；API 與適用公開內容讀回符合；未知結果不盲目重送。
  6. 恢復有明確範圍且已受控實測；第三方改動時不靜默覆寫。
  7. 回訪顯示發布證據、可信量測狀態與下一步；未知不冒充零或增長。
  8. 桌機／手機與必要鍵盤操作走通；使用者不用搬 JSON 或使用工程工具。
  9. 同一候選版本的必要 CI 與獨立 Reviewer 結論完成；不以不同 HEAD 或舊報告補證據。
  10. 真實受邀操作的阻塞已處理；有求助與事故入口，未宣稱尚未實現的自治能力。

先量測：完整流程完成率、第一份可用成果等待時間、建議採納、每人必要決策／求助數、跨登入恢復成功、發布讀回符合、失敗恢復、每輪成本與後續回訪。少量測試者結果要保留分母，不用模糊百分比包裝。SEO 曝光／點擊、GEO 引用與商業成交另依來源及觀察期報告，10/31 不要求立即證明排名成長。

11. 風險、代價與治理簡化

風險具體處理
雙客群、雙平台、自治與美化同時開發保留長期多平台設計；首波只放行單平台完整流程。代價是 YouTube 等候續階段。
舊文件與新 PR 不同步沿用唯一藍圖與一張 Beta 清單；歷史證據保留連結，主表只列目前狀態、同版證據與下一步，不另建治理系統。
安全原型與真服務能力混淆已實作／已測試／已部署／目前可用分列；真模型、真身份、真持久層與真發布各自驗證。
精緻設計最後只成展示把必要 Figma 控制項對到實際 API 行為與錯誤狀態；以操作與截圖比對一起驗收。
